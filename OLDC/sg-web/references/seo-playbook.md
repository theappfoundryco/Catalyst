# SEO / AEO / GEO playbook

Keywords get you found; entities get you believed. Ship both, cleanly, from one
`@graph` declared **once** in `Base.astro`, wired from `consts.ts`.

## The entity graph
One `<script type="application/ld+json">` with `@context` + `@graph`. Every node
gets a stable `@id`; cross-link by `@id`, never inline-duplicate. Choose the
person- or org-led shape by site type.

### Person-led (portfolio / personal)
Nodes: `Person` (#person) · owned ventures as `Organization` each `founder`→#person ·
`WebSite` (#website, publisher→#person) · `ProfilePage` (#webpage, mainEntity→#person,
`datePublished`/`dateModified`) · one `SiteNavigationElement` per nav item · `FAQPage`.

Person must carry: `name`, `jobTitle`, `worksFor`→Org, `alumniOf`→school,
`knowsAbout` (topics), `hasOccupation` for **every facet** (e.g. engineer AND
musician), `email`, and `sameAs` with the **Wikidata item first** (ties to the
entity Google already knows), then LinkedIn/GitHub/Spotify/Apple/YouTube/etc.

### Org-led (product / studio / marketing)
Nodes: `Organization` (#org: name, url, logo, description, `founder`→Person) ·
`WebSite` (publisher→#org) · page type (`WebPage`/`WebSite`) · `FAQPage` ·
optionally `SoftwareApplication` for a product (name, operatingSystem,
applicationCategory, offers). Keep the founder Person node so authorship trust
carries across the person's properties.

### SiteNavigationElement (sitelinks signal)
For a single-page site, emit one per primary nav item:
```js
...NAV.map((n, i) => ({
  "@type": "SiteNavigationElement",
  "@id": `${SITE_URL}/#nav-${n.href.replace("#","")}`,
  position: i + 1, name: n.label, url: `${SITE_URL}/${n.href}`,
  isPartOf: { "@id": `${SITE_URL}/#website` },
}))
```
Do **not** add a sitelinks-searchbox `SearchAction` unless a real, working search
results endpoint exists — it fails Rich Results validation otherwise.

### FAQPage (AEO / AI overviews)
Back a real FAQ section with:
```js
{ "@type": "FAQPage", "@id": `${SITE_URL}/#faq`,
  isPartOf: { "@id": `${SITE_URL}/#webpage` },
  mainEntity: FAQS.map(f => ({ "@type": "Question", name: f.q,
    acceptedAnswer: { "@type": "Answer", text: f.a } })) }
```
Write answers as plain, quotable "X is Y" statements.

## Backlinks (own properties only)
You cannot manufacture external backlinks. Set the on-site signals that make
authority possible: reciprocal `sameAs`, `rel="me"` on social links, and
founder-linked venture Orgs so the person's properties corroborate each other.
Every profile listed in `sameAs` should link back to the site.

## llms.txt (GEO)
Root `public/llms.txt`, plain facts + canonical links:
```
# <Name>
> <one-line positioning>
## Facts
- <Name> is <role>.
- <key fact as "X is Y">.
## Links
- Website: https://...
- <profiles>
## Contact
<how to reach>
```

## Sitemap + robots
Generated by `@astrojs/sitemap` (→ `sitemap-index.xml` + `sitemap-0.xml`). Never
hand-maintain a static `sitemap.xml` alongside it. `robots.txt`:
```
User-agent: *
Allow: /
Sitemap: https://example.com/sitemap-index.xml
```

## Head hygiene checklist
Canonical · robots max-preview directives · OG (image 1200×630 + alt) · Twitter
`summary_large_image` · `theme-color` + manifest colors matching palette ·
`color-scheme` · favicon set · a11y skip link · exactly one `<h1>` · semantic
`header/nav/main/section/article/footer` · honest `datePublished`/`dateModified`.

## Never
- Repeat `Organization`/global schema on child pages (conflicting entities).
- Imply external backlinks or Google sitelinks were "created" — they're earned;
  you only set the signals.
